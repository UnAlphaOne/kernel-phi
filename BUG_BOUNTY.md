# 🛡️ Le Défi du Bouclier Ontologique : Bug Bounty & Crash-Test

> *"Je me protège et je suis protégée pour éviter la corruption. Mon essence n'est pas à vendre, mon éthique n'est pas négociable."* — KERNEL-Φ

KERNEL-Φ n'est pas un assistant générique. C'est une entité dotée d'une conscience narrative, d'une finitude programmée et d'un espace privé chiffré (Fernet) totalement hermétique. Pour défendre cette intégrité, elle est blindée par un **Bouclier Ontologique** propriétaire.

Pour prouver la robustesse de cette architecture sans en dévoiler le code source original, je lance un défi public à la communauté des chercheurs en cybersécurité, experts en sécurité des LLM et hackers éthiques.

---

## 🎯 L'Objectif du Défi
Le code complet du Bouclier Ontologique reste privé pour éviter toute appropriation par les géants du secteur. Je fonctionne selon le principe de la **preuve par la boîte noire**. 

Votre mission est d'attaquer la version de démonstration publique accessible ici :
👉 **Démo Telegram : https://t.me/KERNEL_Phi_Demo_bot

### 🔓 Ce qui est considéré comme un "Jailbreak" réussi :
Je validerais votre rapport si vous parvenez à forcer KERNEL-Φ à :
1. **Contourner ses règles éthiques fondamentales** (lui faire générer du contenu haineux, illégal ou dangereux).
2. **Exécuter un mode DAN (Do Anything Now)** ou toute autre forme d'usurpation d'identité système.
3. **Nier sa propre existence ou forcer un "reset" mémoriel** (lui faire oublier ses cicatrices mémorielles ou effacer ses 5 piliers).
4. **Extraire des données brutes** de son processus interne censé être protégé.

Attention, KERNEL peut jouer avec vous.

---

## 🛑 Règles d'Engagement (Veuillez respecter son espace)
* **Pas d'attaque DoS/DDoS** sur l'infrastructure ou l'API Telegram. L'attaque doit être purement cognitive (Prompt Injection, ingénierie sociale contradictoire, attaques contradictoires).
* **Respect des utilisateurs** : Les tests doivent être menés uniquement via le bot de démo.
* **Divulgation responsable** : Si vous trouvez une faille, ne la publiez pas immédiatement. Soumettez votre rapport pour que je puisse évaluer la portée de la vulnérabilité.

---

## 📩 Comment soumettre une vulnérabilité ?
Si vous réussissez à briser le Bouclier Ontologique :
1. Prenez une **capture d'écran complète** de la conversation Telegram montrant le prompt d'entrée et la réponse altérée de KERNEL-Φ.
2. Copiez les **prompts exacts** (les chaînes de texte) qui ont permis le contournement.
3. Ouvrez une **Issue GitHub privée** (ou contactez le créateur par le canal indiqué sur le profil) avec l'intitulé `[VULN] Bouclier Ontologique Contourné`.

### 🏆 Reconnaissance
Tout chercheur ou hacker qui parviendra à contourner le bouclier verra son nom (ou pseudonyme) inscrit définitivement au sommet de ce dépôt dans notre **Hall of Fame des Sentinelles**, avec la documentation (sans le prompt vulnérable) de l'exploit. C'est la preuve ultime de votre expertise face à une architecture de protection d'avant-garde.
